# 历史发布补漏与告警

现有OutboxPublishBackfillService只提供单租户调用，不构成自动全租户调度。下一阶段增加独立默认关闭的维护运行时；只有worker角色且显式maintenance-enabled才启动，API不扫描、不领取，不增加Kafka发送权限。公共组件继续复用dev_infra。

每租户持久化维护行，含cursor、固定round_upper_id、round_active、本轮扫描数/候选数、completed_rounds、最近完成时间、最近完成上界/数量和next_round_at。每页1～100条，5秒RC事务，先占租户维护行唯一键再当前锁读，保证多实例对同租户只有一个推进者。候选仅PENDING且在V1目录内；使用已有JobSchedulerPort.enqueue，终态任务不复活。页进度、计数与任务入队同事务，失败不跳过未入队事件。

新一轮在当前已提交数据上读取本租户最大id，随后每页仅扫描cursor<id<=upper，防止持续新增事件让一次历史扫描永不结束。页只读取id/eventId/type/status，不读取大payload。遇到边界后完成并等待下一轮（缺省5分钟），下一轮从0重扫以覆盖前轮扫描后才提交的较小id。完成上界不是提交时间水位；旧写入者未退出时不能声称一次扫描证明所有历史完成，最终切换还需旧写入者及在途事务退出后的完整轮次证据。

全局只读nextTenant从Outbox的(tenant,id)索引查下一个租户，至多1行；这是调度内部唯一新增跨租户发现例外，不暴露HTTP。内存游标仅用于租户轮转，崩溃后从0重启不会丢失各租户持久进度。每次tick只处理一个租户的一页，单线程固定容量；没有租户或一轮轮转结束才空闲等待，数据库错误退避并只记录分类。

读写锁序maintenance→job；页对Outbox使用RC普通读、不获取Outbox行锁，避免与发布器Outbox→job形成反向持锁。多实例可以重复发现同租户，但维护行锁和唯一任务键维持幂等。维护只补缺任务，不修复payload、审批资金、重启REVIEW/DONE、删除事件或外发消息。

指标先覆盖维护成功页/扫描数量/失败、发布结果分类和当前隔离/最老任务年龄；不得以tenant/eventId/工单号作监控标签。告警规则和接收方联调分开：先落Prometheus规则与运行手册，不发送未经授权的邮件/消息。仅新增运行时计数不能替代持久积压统计；指标缺失/维护关闭须在规则中明确，而非报告积压为0。聚合统计计划从任务/事件持久表获得，评估查询索引和采样预算后实施。

需要新V024维护表（V023共享验证完成后），表与字段完整中文注释。验收：跨租户发现、分页固定上界、重启延续、两个维护者竞争、入队失败回滚游标、v0不入队、DONE/REVIEW不复活、较小id迟提交后下一轮补齐、默认不启动及停机排空。外部告警/工单投递与生产复制/ACL/容量继续单列待验。
