# 会员不可逆消费事实

## 范围与合同

实现原交易设计 TC-19／20／29／30 的会员事实前置能力，不表示这些完整支付／退款案例已经通过。当前没有真实收款入口调用此端口；下一阶段必须将正常收款、订单支付、库存确认、资金账本和本事实放入同一事务。客户端不能写入或指定首单结果。

内部接口 `MemberTradeFactPort`：

- `confirmPaidOrder(tenant, member, order, amount, currency)`：仅可信正常收款编排调用，必须存在外层事务；上游负责真实验签、足额同币种、订单支付转换及异常资金分类。
- `read(tenant, member)`：交易主库单语句消费快照；调用方负责身份及访问权限。返回 everPaid、firstPaidOrderId、firstConfirmedAt、paidOrderCount、factVersion。

没有新增 HTTP API，既有 35 个操作保持不变。正式新客策略查询、订单奖励证据接口、服务身份权限与正式 V1 事件仍待交付；不能把此内部读方法当作营销资格预占。

## 事务流程

1. 上游先验证真实收款并锁定订单；异常金额、多付或关单后矛盾收款只记录资金／补偿，不调用消费认定。
2. 本端口锁定注册时建立的会员消费事实行，不要求会员仍为 ACTIVE。
3. 当前读查询订单级永久记录：同订单、同金额币种返回原结果；内容冲突拒绝，不覆盖旧事实。
4. 无历史记录时，在取得锁后读取服务器时钟。首次有效订单使用 `FIRST_CONFIRMED_PAID_ORDER_V1`；不接收渠道时间排序参数。
5. 插入不可变订单认定，累加 paidOrderCount 和事实 version，只有 everPaid=false 时设置首单字段。
6. 追加内部待发布事件，与上游外层事务一起提交或回滚。退款不得递减计数、清除 everPaid 或重选首单。

事实的现有 `version` 字段就是返回的 factVersion，不增加含义重复的版本列。订单认定的 factVersion 保留当时版本；重放返回原版本，读聚合得到最新版本。

## 数据与隔离

V006 新增 `tc_member_paid_order`（所有表／字段均中文注释），扩展 `tc_member_trade_fact.paid_order_count`。约束包括：

- 租户＋订单唯一：不依赖可能被清理的 HTTP 命令记录。
- 租户＋会员＋首单槽位唯一：首单槽位为 1，其余 NULL，防止产生两笔首单。
- 租户＋会员＋事实版本唯一：一个版本只有一笔新增消费。
- 订单复合外键绑定租户、订单、所属会员，防止同租户误归属。
- 正金额、安全整数边界、大写币种、固定策略版本、首付聚合字段一致性 CHECK。

所有查询／更新经 MemberTradeFactMapper＋XML；读锁使用当前读，保留 STATEMENT 一级缓存、禁用二级缓存。没有引入新中间件。

升级前置：V005 尚无正常支付写入实现，当前共享库预检查消费历史为零。V006 不尝试推测或覆盖已有消费历史；若其他环境已有 everPaid 数据，必须先提供真实订单历史回填方案，再执行迁移。DDL 不是可事务回滚操作；使用向前兼容修复，禁止回滚删表或清空事实。

## 测试与剩余风险

FoundationTest 新增覆盖两订单并发及 100 次重放、时钟回拨仍不换首单、外层失败全部回滚、无外层事务拒绝、旧 MVCC 快照下当前读去重、金额／币种冲突、零／负／越界金额、跨租户／会员隔离、冻结后资金事实认定。原冻结保留历史测试改为经端口生成真实关联订单认定，替换非法裸写 fixture；不删除原断言。

独立审查后额外补充：两个重叠事务中首候选回滚后另一订单成为首单、跨租户订单写入复合FK拒绝、直接隔离SQL验证首单／订单／版本唯一及金额／币种／策略／聚合CHECK，防止只测Service正常路径。

这些是内部端口集成测试，使用隔离数据库和测试调用方，不是已验签支付或退款闭环。100 次任务使用现有 12 线程池，不冒充 100 并发或生产压测。尚缺真实支付回调、退款后的新客查询、正式事件消费、可靠关单、容量及故障演练证据。
