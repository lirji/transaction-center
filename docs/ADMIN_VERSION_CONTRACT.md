# 管理更新版本合同

落实原外部合同02第12行：管理更新携带If-Match，过期返回412，列表与详情携带版本。

本批覆盖现有10个带expectedVersion的管理写入口：会员状态、商品编辑/发布/下架、SKU添加/编辑、商户状态、退款策略、对账差异查询、Outbox受控重放。保留JSON expectedVersion作为现有命令幂等正文的一部分，强If-Match必须与其一致；缺少头428，非单个规范强整数字符串400，头与正文不同412，服务内版本冲突映射412。普通会员资料/同意不扩大到本次管理合同范围。

共用解析器也用于已符合合同的准入和退货验收入口，保持原幂等重放返回原结果：不在Commands前读当前版本，因此合法重放不因后续资源版本变动被拒绝。无新DDL。商品管理详情、商户/退款策略详情返回ETag，列表已有version字段。权限过滤保持在业务处理之前，资源仍由租户限定。

验证：缺失/弱标签/多值/溢出/正文不符、实际过期更新412、重复成功只一份审计/副作用、双租户和权限、对应旧HTTP回归。OpenAPI在这10个操作声明必需If-Match及400/412/428；原预期版本字段保留。

原商品/SKU合并错误已拆分：仅CAS失败后同事务当前锁读，不存在404、版本过期412、当前版本状态不允许409；对账/Outbox沿现有行锁同样区分版本与状态，不增加读或改动永久回执顺序。
