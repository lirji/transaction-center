# 交易退款操作审计归档

V052 为交易服务建立独立的归档清单、恢复工单与临时查询区。归档范围从部署配置选择一个交易租户。证据以交易退款主键核对入档，历史退款仍可按旧原生编号查找。公开回读保留可读订单、退款、收款及审批编号，没有展示编号的旧记录保留原引用。

## 归档与重试

`tradeRefundAuditArchiveVerify` 接收一条精确退款编号。空参数尝试补办一个已领取批次。只从满足配置年龄的已确认终态退款提取证据，晚到结果及关联流水的最后记录时间也计入年龄。单次最多 200 条关联及操作证据。达到预算上限后的记录继续保留原处供独立处理。

档案写入带格式版本的压缩 NDJSON。清单持久保存固定快照摘要、条数、事实时间范围、对象键和精确对象版本。相同快照复用同一批次，先通过条件写上传，再按指定版本回读校验。同租户只允许一个待核验批次，存储故障恢复后先补办该批次。确认档案后释放领取时的临时字节。恢复和归档异常均不调用审批、渠道或资金写入。退款、审批收件、渠道原文、对账和账本继续由原领域保管。渠道引用只记录本地验真接收号和稳定状态。退货引用须同时匹配原订单及退款所对应的冻结商品明细，关系码为 `ORDER_ITEM`。

## 工单授权

- 使用 `TRADE_REFUND_ARCHIVE_ENABLED` 开启归档模块，设置租户、版本桶、最小年龄及分离的存储身份。写入身份只获本租户档案前缀的必要读写和版本状态读取。恢复身份只读精确对象版本。服务可复用公共 XXL-JOB，执行器标识为 `trade-refund-audit-archive`，注册由 `TRADE_REFUND_ARCHIVE_SCHEDULER_ENABLED` 单独启用。
- 准许恢复的人员及独立审批人在工单中以认证身份摘要登记，工单绑定租户、批次、操作者及有效期。通过 `TRADE_REFUND_ARCHIVE_RECOVERY_ENABLED` 单独开启恢复接口。POST 只发布到临时区和返回行数，GET 要求独立读取权限并再次核对有效工单。
- 临时副本的有效期不晚于工单到期，单次保留最多七天。任务 `tradeRefundAuditArchiveCleanRestored` 每轮清理最多 200 条已过期副本。工单撤销后即时拒绝读取。恢复及读取分别留痕。

正式在线移除及对象销毁要按已签收策略、保全、恢复与容量验收单独放行。领域余额及事实表继续由本领域原有生命周期维护。

## 隔离验证

从空白 MySQL 8.4.11 应用到 V052。以实际订单、退款、审批收件、验真渠道回执和退货明细生成档案。版本化测试桶验证写入回包丢失、同批续办、内容校验、损坏对象拒绝和过期临时副本清理。HTTP 测试核对管理员、恢复专岗及读取专岗的权限，独立验证跨租户或错误人员的工单拒绝和授权撤销。正常归档前后资金账本和在线操作证据一致。归档专项、退款留痕回归及 OpenAPI 共 3 项通过，证据位于 `.local/operation-audit/oa09a-mysql-minio-http.log`。
