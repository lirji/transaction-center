# 审查报告

范围：本轮两个测试Java文件、验证脚本、CI及合同基线；由同一Agent在实现后单独审查，不宣称独立外部评审。之前配置/前端/种子改动保留。

| 发现 | 风险 | 处理 |
| --- | --- | --- |
| 启动ready文件直接写 | 父进程发现文件时可能尚未完整写入JSON | 临时文件加原子rename；结果文件同样处理 |
| 双Worker简单顺序发送可能未形成重叠 | 只能证明先后领取，争抢证据不足 | 两进程各自进入等待屏障后同时释放，只有一个CLAIMED |
| 仅校验旧任务完成被拒绝 | 可能遗漏业务副作用先提交的问题 | 真实库存adjust先写，再同事务complete，旧fence失败后核对整笔库存与流水回滚 |
| 父JVM意外退出可能遗留子进程 | 持续占用端口/数据库连接 | 记录所有Process句柄，JUnit cleanup及父JVM shutdown hook只清理本轮PID |
| 本机环境开关影响测试 | 可能无意启用Outbox/外部适配 | 子进程过滤TRADE/SPRING环境，显式关闭后台/自动准入/归因等可选能力 |
| 营销草案与交易原生证据路径/字段不兼容 | 误把批量接口当首单接口、paid当settled、忽略待退款金额 | 合同基线逐项标明现有形状、禁止转换和适配门禁，不修改生产API掩盖差异 |

确认未新增生产HTTP控制接口、数据库迁移或生产业务状态变更。测试控制仅用父进程stdin与专属文件，生产jar不得包含测试驱动。故障使用真实SIGSTOP/SIGCONT/进程退出与自然数据库时钟到期，不通过SQL改租约时间。

残余：Worker为受控生产批次，不代表八类常驻调度/真实渠道部署；测试涉及的库存写入是fencing事务探针，不表示RECON_QUERY会在生产修改库存。跨库协议、容量、真实渠道及外部合同签收保持独立待办。父进程自身被SIGKILL时无法运行shutdown hook；CI作业容器清理或人工按本次记录PID核对。

结论：本轮范围pass，最终复测与jar检查见QA报告。
