# T12与裂变身份/证据/发布合同执行计划

## 授权与范围

用户已批准执行顺序中的“后端先做T12，同时落实裂变身份／证据／发布合同”。本轮继续该范围，不另行请求重复批准。保留当前交易、营销、权益工作区；不提交推送、不启用共享Worker、不拆库。

## 方案

T12 go：独立Testcontainers MySQL，两个API JVM、两个Worker角色JVM，以测试classpath管道驱动生产JobLeaseService及PaymentRecoveryWorker。故障只针对本次创建的PID，使用真实时钟租约过期及进程暂停/恢复/退出；不改数据库时间或伪造fencing结果。测试驱动手动批次便于精确复现，常驻调度/全通道部署仍属T10。生产代码只有发现可复现缺陷才修改。

合同 conditional-go：核对认证、交易与营销源码，形成身份/证据/发布逐字段映射、调用责任、失败语义、版本与验收矩阵。能确认的按现有合同固定，缺少权威来源或业务决定的明确阻塞；不把文档落实说成真实适配部署。
