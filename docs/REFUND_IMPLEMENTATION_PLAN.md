## 当前依据与职责

现有`tc_payment_receipt`的refunded_amount与refund_reserved_amount由PaymentRefundPort维护，二者和不超过实收的CHECK保留；V013新增支付域永久退款hold并扩展`tc_money_ledger`的REFUND方向与来源引用。V014已有transaction-refund应用模块。退款必须基于真实收款而非仅订单应付金额，异常多付也有独立退款来源，不能把正常订单净消费额增大。

已建立`transaction-refund`领域模块；payment继续拥有收款/退款额度/资金账本，order拥有冻结订单明细与履约事实，refund拥有退款申请、分配、审批、执行状态。跨模块只经过公开Port，禁止refund直接读写PaymentMapper/OrderMapper或其表；各Port加入同一数据源事务。SQL全在所属Mapper/XML，新增表/字段中文注释。

## 实施阶段（连续推进，不逐阶段重新确认）

1. 本地退款申请与额度：payment新增退款来源读取/锁定/预占/释放/确认Port及强类型模型；order提供本人授权和冻结明细退款上限Port；refund新增申请/明细/永久业务幂等与状态机。收款总额、每个明细额度、申请及Outbox在同事务变化，失败全回滚。用20并发实收10000各退1000以及同键重放/跨租户/错误归属证明不超退。
2. 审批与原路执行：固定退款政策Port决定普通/大额/异常路径，未配置政策不能默认免审。正常免审能力与大额/异常审批都必须实现，不能用永久全人工审批代替原范围。申请者和批准者分离，绑定approvalRef/decisionVersion，拒绝伪造/过期/重放/自审自批。交易内部先实现可信审批结果Port，现有流程项目后续再改造和联调。
3. 渠道恢复与可信结果：稳定merchant_refund_no、冻结原渠道/商户/原扣款号/币种/金额，网络事务外；REFUND_RECOVER及回调任务纳入有界运行时，不开无租约旁路。UNKNOWN继续占额度，只有经认证的不可再成功终态才释放。成功结果/额度转移/唯一退款账本/事件与fencing同事务；接收耐久证据不能因旧租约而丢弃。
4. 履约、退货与证据：支付事实不改成未支付，首单/everPaid不清除；订单净支付=正常实收-成功退款，在途额单独展示。退款不增加可售库存；退货收货验收和唯一入库操作独立实现，累计退货不超过履约数量。输出版本化事实供营销后续取消资格/追回奖励，不直接调用权益钱包扣款。

## 数据与关键不变量

- `tc_refund`：tenant/refundNo/来源receipt/order/amount/currency/reason/申请主体/永久sourceRequestId/merchantRefundNo/审批引用及版本/状态/渠道结果/时间/版本；`tc_refund_item`冻结商品/运费/税/多付补偿金额归属。正常商品退款必须绑定本订单项，不能用OTHER项绕过明细上限。
- 退款额度成功+预占≤实收；每项成功+预占≤冻结可退额。用条件更新/行锁/数据库CHECK共同保障，禁止先查余额后无条件写。
- 锁顺序统一订单→支付意图/收款→退款聚合/明细→会员事实（如需）→任务末尾fencing；代码实现前复核与现有支付/取消锁序兼容。不能事务内等待审批或渠道。
- 明细总和必须等于退款金额；首期无优惠分摊，仍区分商品/运费/税。未来折扣采用冻结的确定性最大余数分配，不能退款时重算。
- 永久业务去重不依赖HTTP幂等记录保留期；重复可信成功不重复返款或记账。已派发或UNKNOWN不可被管理员直接改为拒绝并释放额度。
- 新迁移从共享最新版本之后递增；不修改V001～已执行版本。已有RECEIPT流水历史保持不变，只扩展允许的退款类型和可靠引用。

## API交付顺序

原合同保留：POST `/api/v1/trade/orders/{orderNo}/refunds`；GET `/api/v1/trade/refunds/{refundNo}`；后台只读退款列表；经专用scope与真实签名的审批回执入口（不开放裸admin approve/reject）；验签后退款回调入口。所有写入含幂等、权限、版本/归属校验及审计。本人申请与后台批准权限不同；供应商回调成功应答只代表耐久接收，不宣称业务已经处理。

先实现内部合同和本地可测试状态，再接HTTP/OpenAPI与真实外部合同；不能公开一个允许用户提交“退款成功”的接口。前端仍交Cursor。

## 验收与外部缺口

按TC21～25验证并发额度、断网未知、重复成功、商品/运费/税分配、自审自批及退货独立；按TC20/27/29验证退款不变新客、乱序事件版本、冻结/匿名化后的合法资金处理。补旧租约回滚、不同审批版本、权限和金额边界、全量回归、独立高风险审查。真实退款供应商期限/部分退款次数/账单/永久幂等、审批身份联调、生产容量/容灾及营销追回保留为必需验收，不以模拟替代。

常驻队列年龄/采集告警/配额、真实风险/支付渠道、KMS、正式消息和CI等前序缺口继续并行纳入交易中心完整门禁，交易完成后再改现有项目。
