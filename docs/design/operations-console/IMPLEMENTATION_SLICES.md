# 交易运营控制台实施与工作计划

以当前 `docs/openapi.json`、管理查询 Controller、只读 DTO 和 Mapper 为契约。延续现有 React、React Router、TanStack Query、组件与权限。实施顺序为 S1 → S2 → S3 → S4 → S5 → S6。每个切片有独立验收，按完整逻辑单元提交。开发和浏览器验收复用本地 Compose 的既有依赖及演示数据，涉及写入的测试使用隔离数据。

| 切片 | 可交付结果与工作项 | 依赖 | 范围 | 可观察验收 |
|---|---|---|---|---|
| S1 订单详情 | 优先读订单主详情。履约来自主详情，支付、实收、退款、退货、限权证据按分区读取。保留筛选、查询游标及返回位置，支持读取失败后重试 | 现有管理查询、队列和作用域 | 前端订单、API client、针对性回归 | 首次请求只有订单主详情；选中分区才发出对应 GET；管理读取返回 429 后可局部重试；从带筛选的订单列表返回可继续查看 |
| S2 运营工作台 | 首屏显示商户及受理状态，异常实收、待审批退款、未结对账和发布异常进入实际筛选队列。核对空态、读取失败和可见权限 | S1，现有队列 API | 前端工作台、对账与发布隔离等目标页 | 链接条件与首页样本一致；队列空与暂不可读分别显示；展示当前返回条数或限定样本，不将其合计为全库总数 |
| S3 资金与售后队列 | 实收增加异常快捷筛选，拆分订单、支付、渠道和金额字段；退款展示审批截止与真实状态快捷筛选，政策进入独立操作区并保留版本校验 | S2，现有实收和退款 DTO | 前端实收、退款及共享展示 | 通过已有筛选契约定位异常实收及待审批退款；日期采用北京时间显示；政策编辑初值取当前币种 |
| S4 运营列表规范 | 先覆盖订单、支付、报价与退货，再覆盖商品、库存、会员、条款、商户、渠道、履约和运行管理；按实际返回字段独立分列，统一筛选文案、时间与恢复原查询体验 | S3，共享展示和查询原语 | 前端列表、相应详情及必要选择器 | 表头与查询名一致，时区切换后业务时间不变，现有动作与权限兼容；新增跨页筛选由 S5 交付 |
| S5 查询投影补足 | 按价值依次设计审批临期、异常资金时间、稳定排序，以及商品、库存、会员等跨页查询契约，逐个补齐 Mapper 投影与 UI | S4；现有 API 的兼容扩展和分页语义有明确依据 | 后端查询、OpenAPI、按需索引与前端消费 | 用完整页范围验收筛选及排序，保留原调用行为；新查询均限制租户与范围 |
| S6 经营汇总 | 定义并验证新建订单、正常确认收款、已确认退款、期间净收款等指标。用同一时间和币种口径实现汇总及明细入口，之后评估会员和试点经营投影 | S5；需明确正常资金、异常资金、退款入账的口径及权威时间 | 后端只读汇总、Mapper、契约与工作台 | 正常、异常、零元、多币种、在途与空区间有真实数据库样本。汇总与同口径明细可核对 |

S1–S4 复用正式契约按序实施。S5–S6 先评审各自的兼容契约、数据口径和索引需求，再绑定可用接口。跨平台成本、结算、店铺及营销指标进入当前服务前要获得对应权威来源。各切片共享控制台原语和发布分支，按序收口并复验。

## 首批实施进度

S1、S2、S3 已实现。S4 已完成共享筛选布局、固定北京时间输入及订单、支付、报价、退货的首批列表调整。其余基础资料、履约和运行管理页面继续按 S4 推进，随后进入 S5、S6。

首批验收包括订单主详情单请求与关联分区读取、429 后局部恢复、四个工作台入口携带真实筛选、实收异常筛选、退款截止和政策币种保留。北京时间查询按洛杉矶和上海设备时区对照，得到相同 UTC 查询边界。
