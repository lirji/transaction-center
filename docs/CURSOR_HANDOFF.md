# Cursor前端交接：交易中心首批

前端由Cursor负责，本仓库本轮只实现后端，不创建页面或页面内Mock数据。

新增会员消费事实内部Port不增加HTTP操作；不要创建“手工确认支付／修改首单”按钮。会员everPaid展示仍从既有接口获取，正式支付／新客资格接口须等待后续OpenAPI交付。

2026-09-07后端已改为MyBatis Mapper＋XML，原22个HTTP操作不变，新增6个多SKU／报价操作，报价阶段共28个；订单阶段新增7个，支付核心再新增4个，目前共39个。见[多SKU与报价](SKU_AND_QUOTE.md)和[订单基础](ORDER_FOUNDATION.md)；[支付受理与查询](PAYMENT_CORE.md)已交付，但202仅表示本地持久受理，没有paymentAction或真实渠道执行器，禁止构造真实付款跳转；退款入口尚未交付。

- 基地址默认 `http://127.0.0.1:8400`，通过同源开发代理调用，后端不开放通配跨域。令牌由既有登录体系签发并配置本项目issuer/audience，不自行拼接JWT或tenant请求头。
- 接口以 [openapi.json](openapi.json) 为准；生产设计列出的其余接口尚未实现，暂不展示可操作入口。
- 当前可做：会员展示／注册／展示名编辑、会员管理列表／冻结／解冻、条款发布／列表和本人同意历史；商品列表／详情／草稿编辑／多SKU管理／发布／下架，以及服务端报价；仓库创建／列表、库存余额／盘点／按仓库SKU的流水查询。
- 所有写命令返回resourceId；对相同用户动作生成并保留Idempotency-Key直到确定结果，相同键不得换请求内容。修改商品需发送上次读取的expectedVersion，409时重新读取，不无条件重试覆盖。
- 金额为最小单位整数，展示转换不能改变提交值；资源ID按字符串保存。列表以after/limit有界分页，使用末条ID作为下一页游标。
- 数据必须来自数据库API；dev-seed可创建演示商品和库存，禁止写死商品、会员或库存数组。演示租户必须由合法签名身份声明匹配900001才可读取。
- 不做前端直接预占／释放库存，不把商品列表中的价格当订单支付金额，不显示真实支付入口。报价只能表示锁定价格，不预占库存或代表首单成功；订单创建／查询／取消已交付；CLOSING必须显示等待资金关单，不能当取消成功。支付与退款仍另行交接。

会员变更注意：

- `/members/me` 与 `/admin/members` 返回version，修改资料、同意动作、冻结／解冻均须提交expectedVersion；它们共用会员版本，不能各自缓存互不相关的版本号。
- 冻结后资料修改和新增同意返回422 MEMBER_FROZEN，读取历史与撤回同意仍允许。401需要登录，403无权限，409须读取最新状态再决定是否重试，不能换幂等键盲提交。
- 条款先由后台发布不可变版本，再展示给会员；发布URL必须HTTPS，页面展示内容应与contentHash对应。注册不会自动同意营销条款。
- 同意历史按事件ID正序分页。某用途的有效动作取最大memberVersion，不按documentVersion字符串排序；撤回必须对应该用途最近GRANT的版本。新旧请求乱序或重复响应不能重新勾选已经撤回的授权。
- 库存流水查询必填warehouseId和skuId，所有列表limit≤100。不要发送缺少过滤条件的全库导出请求。
