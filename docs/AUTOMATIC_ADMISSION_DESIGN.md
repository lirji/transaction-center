# 积压与磁盘自动准入保护

来源：原03-FINAL_PLAN第178行，消息故障由Outbox保留事实，积压触达磁盘安全预算时停止新增写流量。已有人工租户策略继续保留，不把自动恢复覆盖到管理员手动暂停上。

## 接入已有受理边界

继续使用 AdmissionService.acquire 返回的有效策略；订单在新建之前requireOrder，支付仅在确需新增意图/尝试之前requirePayment。幂等已完成回放、已有支付尝试返回、回调、退款、查单和后台恢复不受暂停影响。自动保护只与人工策略做逻辑AND，不改人工版本、不制造伪管理审计。

每个API进程只读取内存安全快照，网络/文件系统探测在单一周期采样线程完成，不能放进交易事务。启动时自动保护开关默认false；明确启用后，在首个有效样本之前及样本过期时拒绝新增订单和支付。停采样不能遗留永久允许状态。指标固定标签，不含业务身份。

## 信号与恢复

复用OutboxQueueSnapshotPort读取READY/RUNNING/REVIEW三类全局计数下界。当前上限每状态10001，因此阈值不得大于10001的可判断范围，不能把截断计数当精确值。总积压高阈值进入暂停，低阈值才允许恢复；样本时钟异常、数据库失败或过期进入暂停。人工策略仍单独生效。

磁盘信号必须对应实际持久数据库存储卷，不能用API容器根分区空闲空间代替MySQL磁盘。单机开发可显式挂载/指定同一存储卷并核对；远程/托管数据库需接入运维权威监控信号。启用磁盘保护必须具备此映射，未知或过期信号失败关闭。保留恢复业务所需安全余量，阈值由部署预算配置；不能在没有容量数据时声称生产阈值已验收。

## 待实现与验证

已实现core内存保护状态与server周期采样适配，21项初轮专项与修后16项检查通过；有界采样失败、滞回、过期、人工暂停不被恢复覆盖已验证。真实MySQL存储卷映射和容量验收仍待环境证据，不以临时目录测试替代。避免新增远程可写运维控制接口，复用现有配置与可观测机制。


## 部署配置与运行边界

`TRADE_AUTOMATIC_ADMISSION_ENABLED` 默认false；启用必须配置 `TRADE_AUTOMATIC_ADMISSION_DISK_PATH`（绝对路径）与 `TRADE_AUTOMATIC_ADMISSION_DISK_STORE`（FileStore名称）。每次采样重新核对挂载标识，不匹配或路径不可访问即关闭新增受理。远程数据库磁盘尚未映射时不能拿本机路径冒充，本适配器不宣称覆盖托管数据库监控接入。

默认高/低积压阈值10000/5000、磁盘暂停/恢复余量5/10GiB、采样周期15秒、样本有效期45秒，均为可配置初值，需部署容量预算验收。积压三类计数下界求和，命中高阈值暂停；恢复要求总计数不超过低阈值且余量不低于恢复预算。样本从数据库时间计算初始年龄，再用单调时间扣除剩余寿命；已失效样本原子废弃，墙钟回拨不能复活，未来样本拒绝；任何探测失败立即暂停。恢复后人工版本及开关保持不变。

Prometheus `trade_automatic_admission_blocked` 表示自动保护的有效暂停状态，人工开关继续通过原管理查询查看。自动保护不改人工策略行、不生成管理操作历史。停止时先关闭许可，最多等待5秒；底层文件系统调用不可强行中止时保留单个旧线程，禁止重启另开线程，旧结果不能恢复许可。交易在acquire时已经受理的事务继续完成，自动保护不是撤销已受理资金计划的屏障。
