# 履约事实、退货验收与唯一回库

## 原要求及当前缺口

原交易FINAL_PLAN 6.4、DATABASE_DESIGN订单履约/退货表、TC退款退货验收要求仍有效。原OrderService支付确认只把预占变已售；现已新增V020/OrderFulfillmentService内部实际交付与独立商业完成，验证结果见ORDER_FULFILLMENT.md；不能把paidAt当作实际发货/交付凭证，也不能仅凭退款成功增加库存。

## 实现顺序与不变量

1. 订单域增加唯一订单履约事实，可信内部物流/服务交付入口绑定来源系统、永久事件号、原订单及证据引用。首期一单一履约，履约数量来自冻结订单明细。交付和商业完成分开，completedAt只能由独立完成事实推进。先提供内部合同和测试；真实WMS/物流身份验真及HTTP权限尚需后续边界接线，不能开放普通会员提交完成事实。
2. 退货验收作为独立聚合，永久来源事件号、原订单项、接收仓库、收到数量、可售数量、验收证据及验收身份。累计收到数量不超过真实已履约数量；可售数量不能超过收到数量。不合格验收可以留事实但不能增加可售库存，同事件内容改变拒绝。
3. 库存域通过专用Port维护永久退货操作键与原库存预占绑定；原CONFIRMED预占不改回RESERVED/RELEASED。可售回库将sold减量、available加量，stock_total保持不变，以符合当前available+reserved+sold=stock_total定义；不得复用adjust(+quantity)，否则会把已计入总量的原商品再次增加总量。
4. 订单→履约/明细验收预算→库存永久退货键/原预占→余额的固定锁序；独立收货事实、累计预算、唯一库存流水、审计及Outbox同事务。重放在永久键当前读后返回原事实，短期command淘汰不重复回库。新增缺失键避免先FOR UPDATE范围锁再插入造成跨订单死锁。
5. 非可售收到的商品不增加available；本切片不引入残次品仓余额/修复后转可售的隐式行为。跨仓返还要在原售出仓sold减少与接收仓available/total增加、原仓total减少之间保持两仓守恒，按warehouse/sku排序加锁；不能默认把原售出仓余量减到负数。首次实现必须明确支持或保留跨仓边界，不能悄悄忽略已确认接收仓合同。

## 验证

并发与100次重放只产生一份验收/库存流水；不同退货来源累计不超已履约数量；未履约/跨租户/错误订单项拒绝；收到不合格品不回库；部分可售及跨仓守恒；外层回滚全部撤销；退款成功/拒绝/UNKNOWN均不自动创建验收，everPaid不变。正式资格V1需引用净支付、首单与商业完成事实，不能用内部v0替代最终事件合同。

履约前置V020及源码已通过260项全量和独立审查，共享V020已迁移校验；验收/唯一回库表和源码已按本文实现，详见RETURN_RECEIPTS.md；本次最终验证证据见evidence/returns，运行中结果不当作通过。生产验真、仓储联调及运营验收仍须保留。

## 独立设计审查补充

- 跨仓可售r：原仓sold-r、stock_total-r；接收仓available+r、stock_total+r，两仓reserved不变。只处理可售数量，非可售保留验收事实；sold是未回到可售的净售出记账量，不能解释为仍在客户手中的物理库存。
- 排序必须包含余额初始化UPSERT，因为建行/命中旧行时已经加锁。双向退货不能先建目标仓再排序。
- 永久父退货操作派生确定性OUT/IN流水键，两仓余额和两条流水一起提交；一条唯一operation不能直接复用为两行流水。
- 按原CONFIRMED预占累计回库不得超过预占数量，且必须绑定原订单项/SKU；仅检查仓库sold足够可能挪用其他订单已售额。
- 服务商品不接受实物退货；首期全量履约必须有可信实际全量交付证据，不能将发货通知直接当完成。
