> 时效说明（2026-09-08）：本文保留 V020 核心内部合同与历史验证。后续已实现 [履约/退货授权 HTTP 入口](FULFILLMENT_ACCESS_DESIGN.md) 及正式订单生命周期 V1 事件，不能继续将正文“只有内部合同/仍为 v0”当作当前完整范围。入口默认关闭，真实 WMS/服务证据仍待联调；总览见 [业务说明](BUSINESS_GUIDE.md)。

## 内部合同

OrderFulfillmentService.deliver接收已认证可信来源Actor、永久来源事件号、订单号、实际整单交付证据引用及时间；这是全部冻结明细实际交付，不接受部分发货通知。支付可履约状态或零元订单为前置，交付时间不得早于建单或晚于统一Clock。新事实与订单FULFILLING、审计、Outbox同事务；库存已在支付/零元下单时确认，不再次改变库存。

complete要求已有交付事实，完成时间不早于交付且不晚于Clock；另存完成来源事件与证据，再将订单设为COMPLETED并写completedAt。paidAt、财务状态和首单事实均保持不变，后续退款不撤销已发生的交付或商业完成。零元服务完成仍没有消费首单。

交付和完成事件各自永久绑定，短期tc_command淘汰后仍幂等。订单唯一履约和来源事件唯一约束兜底，命令保留期内同键不同内容返回IDEMPOTENCY_CONFLICT，永久事实冲突返回FULFILLMENT_CONFLICT；同订单不同完成事件竞争只接受一个。异常后整事务回滚，不部分保留审计/事件或订单完成。

## 持久化与信任边界

V020增加带完整中文注释的tc_order_fulfillment及5条类型化Mapper SQL。锁序订单→履约；首次交付先INSERT占唯一键后当前读，不对缺失永久键先加范围锁。首期一单一整单履约，实际数量来自冻结订单明细，服务商品后续不得进入实物退货。

目前只有可信内部业务合同，没有公开HTTP写入或生产WMS/物流验真适配。不能把普通会员Actor直接传入这些方法，也不能把内部测试当作真实来源验收。生产来源身份、签名/重放边界、实际物流/服务联调仍未完成。事件仍为内部v0，正式V1资格合同另行实现。
